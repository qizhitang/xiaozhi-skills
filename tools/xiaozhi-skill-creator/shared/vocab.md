# 全库统一词表（单一事实源）

> 本文件是小智伴学全库的**唯一术语与枚举来源**。所有 SKILL.md、references、JSON Schema 只能**引用**本文件的定义，不得在各自正文里另起一套词表或阈值。
> 修改本文件即修改全库契约；修改后请同步更新对应 schema 的 `enum`，并运行 `node scripts/check-skills.mjs`。
> 引用方式：`见 shared/vocab.md §N`。

---

## §1 错因基础四维（全学科通用层）

所有学科的错题在**通用层**只记录以下四维之一（对应 schema：`dna-profile.schema.json#/$defs/errorDimension`、`handover-protocol.schema.json#/…/basicDimension`）：

| 代码 | 维度名 | 一句话判定 | 不是这一维的情况 |
|---|---|---|---|
| `C` | 概念模糊 | 换成"纯净版"最简题也做不对 | 纯净版能做对 → 不是概念问题 |
| `K` | 计算失误 | 思路对、列式对，算错/抄错/漏单位 | 列式就错 → 看 M 或 C |
| `R` | 读题失误 | 把条件读对后立刻会做 | 读对了仍不会 → 看 M 或 C |
| `M` | 方法用错 | 概念清楚、读题无误，但选错工具/路径 | 换题型不会 → 看 C |

判定顺序：先 R（复述条件）→ 再 C（纯净版）→ 再 M（换题型）→ 剩下的归 K。
**同一道错题只记一个主维度**；学科层可以再记一个子类型 ID（§2）。

> 已废弃的同义词（禁止在正文出现）："概念理解错误 / 计算/操作失误 / 审题习惯问题 / 策略选择错误"、"概念 / 计算 / 审题 / 策略"、"知识漏洞 / 规则错误 / 粗心大意"。老师端七类见 §3 映射。

## §2 学科子类型编码（学科层）

子类型 ID = 学科前缀 + 两位数字，定义在各学科的错因维度表中；通用层只存 ID，不解释含义。引用方的技能包内若带有该表，文件名为 `shared/<学科>-error-dimension-table.md`。

| 学科 | 前缀（维度） | 定义文件 |
|---|---|---|
| 数学 | `B`(概念) `C`(计算) `R`(读题) `M`(方法) | 数学错误DNA 的错因维度表 |
| 物理 | `P`(图景) `C`(概念) `F`(公式) `R`(过程) `T`(数学工具) | 物理错误DNA 的错因维度表 |
| 英语 | `G`(语法) `V`(词汇) `T`(表达/中式) `P`(发音) `L`(听力) | 英语语法突破教练 的错因维度表 |
| 语文 | `RC`(阅读) `AR`(答题规范) `WT`(写作) `CL`(文言) `LG`(语病) | 阅读理解拆解师 的错因维度表 |

学科维度 → 通用四维的映射：

| 学科维度 | 通用维度 |
|---|---|
| 数学 B / 物理 C、P / 英语 G、V / 语文 CL | 概念模糊 |
| 数学 C / 物理 T / 英语 P（拼写）| 计算失误 |
| 数学 R / 物理 R（审题部分）/ 英语 L / 语文 RC | 读题失误 |
| 数学 M / 物理 F / 英语 T / 语文 AR、WT、LG | 方法用错 |

## §3 老师端错因七类 ↔ 通用四维

老师端（作业跟进、错因分析、命题）允许使用七类，但写入任何档案或与学生端交换时必须映射：

| 老师端七类 | 通用四维 | 说明 |
|---|---|---|
| 知识漏洞 | 概念模糊 | |
| 规则错误 | 概念模糊 | 规则记错本质是概念 |
| 计算错误 | 计算失误 | |
| 审题错误 | 读题失误 | 含看错数字、漏条件 |
| 策略错误 | 方法用错 | |
| 表达/书写不规范 | 方法用错 | 会做但过程不得分 |
| 习惯性失误（原"粗心大意"） | 计算失误 | 抄错题 → 读题失误。**不使用"粗心"作为原因**，粗心是结果 |

判定互斥规则：一道题只能归一类；"移项不变号"归规则错误（概念），不归计算；"看错数字"归审题，不归习惯性失误。

## §4 弱项状态（五档，唯一）

对应 schema `dna-profile.schema.json#/$defs/weaknessStatus`：

| 状态 | 进入条件 | 离开条件 |
|---|---|---|
| `待处理` | 首次记录错题 | 记录第 2 次 → 初步弱项 |
| `初步弱项` | 同一知识点 + 同一通用维度在 28 天内累计 2 次 | 第 3 次 → 顽固弱项；2 次独立验证做对 → 已攻克 |
| `顽固弱项` | 28 天内累计 3 次（§5） | 首次独立验证做对 → 突破中 |
| `突破中` | 顽固弱项后首次做对 | 再一次独立验证做对（间隔 ≥ 3 天）→ 已攻克；再错 → 顽固弱项 |
| `已攻克` | 连续 2 次独立验证做对（间隔 ≥ 3 天） | 30 天内再错 → 突破中 |

> 已废弃：`无 / 观察 / 顽固`、`正常 / 初步弱项 / 顽固弱项 / 已攻克`（四档）、`已攻克（待验证）`、`已攻克（待巩固）`。

## §5 "3 次顽固"唯一口径

- **粒度**：同一知识点标签 + 同一通用维度（§1）。学科子类型 ID 不同但通用维度相同，**仍计入同一计数**。
- **时间窗**：滚动 28 天。
- **连续 vs 累计**：**累计**（不要求连续），但同一天内同一知识点多次错只计 1 次。
- **计数权威**：学生端由 `xiaozhi-correction-notebook` 唯一计数；学科错误 DNA 只接收错题本推送的"顽固"事件，不自行计数。老师端由 `xiaozhi-teach-homework-tracker` 计数。
- **高危**：同口径 28 天内累计 5 次 → 建议与学生本人沟通策略；是否告知家长依 §8 授权。
- **攻克标准**：连续 2 次独立验证做对，两次间隔 ≥ 3 天，且至少 1 次为"换题型/纯净版"验证。**不存在"3 次才算攻克"**。

## §6 掌握度（学生端三档 ↔ 老师端五档）

| 学生端（`masteryLevel`） | 老师端（`masteryStatus`） | 判定证据 |
|---|---|---|
| 真正掌握 | 已掌握 | 能解释 + 能迁移到新题型 |
| 会解释 | 基本理解 | 能说清为什么，但迁移不稳 |
| 会复述 | 仍需巩固 | 只能复述结论/步骤 |
| （无对应，记为"会复述"并标注） | 需要重讲 | 复述也不完整 |
| （不写入） | 证据不足 | 未验证 |

老师端写回学生端时按左列转换；学生端向老师端共享时按右列转换。

## §7 置信度标签

对应 schema `confidenceLevel`：

| schema 值 | 正文标签 | 含义 | 使用规则 |
|---|---|---|---|
| `data_sufficient` | 🟢 数据充分 | ≥ 3 次独立观察且方向一致 | 可写入长期档案 |
| `preliminary_trend` | 🟡 初步趋势 | 2 次观察或方向基本一致 | 可写入，输出时必须带标签 |
| `insufficient_sample` | 🔴 样本不足 | 单次观察或互相矛盾 | 只在当前会话使用，不写入长期档案 |

> 已废弃：`⚠️`（改用 🟡）、`medium`、无标签的"连续 N 次"结论。

## §8 授权位（谁同意了什么）

对应 schema `dna-profile.schema.json#/meta/consentStatus`：

| 字段 | 含义 | 默认 |
|---|---|---|
| `profileEnabled` | 是否建立长期档案 | false |
| `consentGivenBy` | 同意主体：`学生本人` / `监护人` / `学生与监护人` | 必填于 profileEnabled=true 时 |
| `ageBand` | 学段（§10），用于判断是否需要监护人同意 | `未知` |
| `guardianConsentRequired` | ageBand 为小学各段或初中一年级（约 ≤ 14 周岁）时为 true；此时 `consentGivenBy` 必须含监护人 | 由 ageBand 推导 |
| `crossSkillSharing` | 允许跨 SKILL 共享最小字段 | false |
| `parentSharingConsent` | 允许把学习摘要输出给家长/监护人（家庭看板、月报家长页、家长简报） | false |
| `emotionSharingWithParent` | 允许把**情绪相关**内容输出给家长（独立于上一项，且必须学生本人同意）| false |
| `teacherWritebackConsent` | 允许老师端 SKILL 写回学生档案 | false |
| `reminderConsent` / `emotionTrackingConsent` / `interestTrackingConsent` | 同现有 | false |

规则：
1. 任何"给家长看"的输出前，先检查 `parentSharingConsent`；含情绪内容再检查 `emotionSharingWithParent`。两者任一为 false → 只输出给学生本人，并告诉学生可以自己决定是否转发。
2. **危机例外**（`shared/crisis-exception.md`）优先于以上所有位。
3. 学生与家长共用一个 IM 会话时，SKILL 应先问"现在是同学本人在吗"，无法确认时按"学生本人"处理并不输出家长版内容。

## §9 提醒预算（唯一契约）

- 发送方唯一：只有 `xiaozhi-im-reminder` 发送提醒；其他 SKILL 只能 **入队**（`handover-protocol` 的 `reminder_enqueue`），不能自行承诺"我会在 X 时提醒你"。
- 每日上限：**1 条合并摘要 + 最多 1 条即时提醒**（考试当天/用户明确要求的除外）。合并摘要把当日到期的词卡、错题回看、计划任务合成一条。
- 免打扰窗口按学段（§10）。
- 无回应策略：连续 3 条无回应 → **暂停**该类提醒，用户下次进入会话时询问是否恢复。**不存在"每周 1 次持续唤醒"**。
- 词汇复习：SM-2/间隔序列只在词汇 DNA 内部维护"到期日"，对外每天只贡献 1 张"今日到期词卡"。

## §11 命名

- 协调器统一名称：**学习系统协调器**（`xiaozhi-skill-coordinator`）。废弃"三SKILL联动协调器 / 五SKILL联动协调器 / SKILL联动协调器"。
- 测评类型统一：`形成性` / `终结性` / `诊断性`。废弃"总结性 / 展示性"。
- 版权状态统一（`copyrightStatus`）：`自有` / `改编` / `公开可引用` / `仅存索引`。教辅原题与历年真题一律 `仅存索引`。

## §12 数值表述规范

- 不得出现无出处的比例/倍数（"80% 场景""十倍""85% 的学生"）。经验参数须写成"经验值，约 …"并可被用户调整。
- 不得承诺"治愈 / 消失 / 一定提分"。
- 群体通过率（"70% 的学生能做对"）只能作为**难度描述**，不能作为对个体的判定依据。
