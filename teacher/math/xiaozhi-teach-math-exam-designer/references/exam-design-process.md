# 数学测评设计流程

> 适用学段：初中（7-9 年级）。
> 示例题验算：2026-09-04（本文无需计算的示例题，只有分值区间；09-04 的改动为边界与流程措辞）
> 配合 `xiaozhi-teach-math-exam-designer` 使用。从测评目标出发，6 步走完"目的→蓝图→题目→审查→拼卷→考后统计"全流程。
> 边界：本流程只做命题与题目统计；错因归类、学员分层、补救与讲评编排、家长沟通均转对应 SKILL（见第 7 节）。
> 词表以 `shared/vocab.md` 为准：测评类型三类（诊断性/形成性/终结性）、
> 版权四值（自有/改编/公开可引用/仅存索引）、能力层级用课标四级。

## 1. 测评设计 6 步流程

```text
┌──────────┬────────────────┬────────────────────┐
│ 步骤      │ 名称            │ 关注重心            │
├──────────┼────────────────┼────────────────────┤
│ 第 1 步   │ 明确测评目的    │ 为什么考            │
│ 第 2 步   │ 编制双向细目表  │ 考什么              │
│ 第 3 步   │ 编写/筛选题目   │ 怎么考              │
│ 第 4 步   │ 试卷审查        │ 试卷质量            │
│ 第 5 步   │ 拼卷定稿        │ 形成终稿            │
│ 第 6 步   │ 考后统计与交接  │ 这份卷考出了什么    │
└──────────┴────────────────┴────────────────────┘

第 6 步止于**题目统计**。讲评课怎么上、错因怎么归类、谁要额外补，
分别转 xiaozhi-teach-math-lesson-planner、xiaozhi-teach-math-error-analyzer、
xiaozhi-teach-student-analyzer，本流程只交出字段。
```

## 2. 第 1 步：明确测评目的

### 2.1 4 类测评目的

```text
┌──────────┬──────────────────┬────────────────────┬────────────┐
│ 类型      │ 目的              │ 时机                │ 难度比例    │
├──────────┼──────────────────┼────────────────────┼────────────┤
│ 诊断性    │ 摸清学员水平      │ 开学初/单元初       │ 8:2:0      │
│ 形成性    │ 反馈教学效果      │ 单元中段/章节末     │ 6:3:1      │
│ 终结性    │ 评定学习成果      │ 期末（含中考模拟）  │ 7:2:1      │
└──────────┴──────────────────┴────────────────────┴────────────┘

三类是 `shared/vocab.md §11` 的统一口径，也是 schema `examBlueprint.assessmentType` 的 enum。
选拔性场景（升学/竞赛选拔）不在本 SKILL 范围，用通用版 `xiaozhi-teach-exam-designer`。
```

### 2.2 测评目的设定

```text
【目标 1】知识目标
  · 哪些知识点必须覆盖
  · 覆盖比例

【目标 2】能力目标
  · 主要测哪种能力
  · 能力层级分布

【目标 3】时长目标
  · 总时长
  · 各题时长估算

【目标 4】难度目标
  · 难度梯度比例
  · 平均分预期
```

## 3. 第 2 步：编制双向细目表

（详见 [blueprint-template.md](blueprint-template.md)）

```text
【双向细目表结构】
  · 纵轴：知识点（章-节-点）
  · 横轴：能力层级（**课标四级：了解 / 理解 / 掌握 / 运用**）
    —— 与 SKILL.md §5.2、schema cognitiveLevel 完全一致；
       习惯 Bloom 的按 记忆→了解、理解→理解、应用→掌握、分析评价创造→运用 换算
  · 交叉点：题目数量 + 分数

【细目表填写要素】
  · 题号
  · 题型
  · 分值
  · 预估难度
  · 预估通过率
```

## 4. 第 3 步：编写/筛选题目

### 4.1 题目来源 4 类

```text
来源 ① 自编
  · 优点：完全可控
  · 缺点：耗时
  · 占比建议：30-50%

来源 ② 改编
  · 来源：教材例题/习题改编
  · 占比建议：20-30%

来源 ③ 现成题库
  · 来源：学校题库/历年真题
  · 占比建议：20-40%

来源 ④ 学员错题改编
  · 来源：班级学员常见错题
  · 占比建议：10-20%
```

### 4.2 题目版权标注

版权状态只用 `shared/vocab.md §11` 的四个枚举值（与 schema、SKILL.md 完全一致）：

```text
┌────────────┬────────────────────────────┬────────────────────┐
│ copyrightStatus │ 来源                   │ 入库方式            │
├────────────┼────────────────────────────┼────────────────────┤
│ 自有        │ 老师原创                    │ 全文入库            │
│ 改编        │ 基于教材/经典题改编          │ 全文入库 + 注明来源  │
│ 公开可引用  │ 教材原题、CC 协议、已获授权   │ 全文入库 + 标注出处  │
│ 仅存索引    │ 教辅原题、历年真题           │ 只记题号与出处，     │
│            │                            │ **不复制题面**      │
└────────────┴────────────────────────────┴────────────────────┘

旧版的"自创/授权/公有/未授权"四态已废止（与 schema 的 enum 对不上）。
❌ 未授权复制教辅题库、未授权转载网络题库：一律不做。
```

### 4.3 编写题目 5 原则

```text
原则 1：题干清晰
  · 一道题只有一个明确问法
  · 避免歧义
  · 字数控制

原则 2：考点单一
  · 一道题突出一个核心考点
  · 避免多个考点混在一起
  · 综合性题放最后

原则 3：难度梯度
  · 由易到难
  · 跳过式设计
  · 让学员有"成就感"

原则 4：公平性
  · 不超出课程标准
  · 不依赖超纲知识
  · 题目信息对所有学员公平

原则 5：可区分性
  · 不同能力层级学员有不同表现
  · 高分段学员有发挥空间
  · 低分段学员有基础分
```

## 5. 第 4 步：试卷审查

### 5.1 试卷审查 6 维

```text
┌──────┬────────────────┬──────┐
│ 维度  │ 检查项          │ 通过  │
├──────┼────────────────┼──────┤
│ 知识  │ 是否覆盖大纲    │ □     │
│ 能力  │ 各层级分布合理  │ □     │
│ 难度  │ 难度梯度合理    │ □     │
│ 题量  │ 时长足够        │ □     │
│ 公平  │ 无超纲/歧视     │ □     │
│ 表述  │ 无歧义/错字     │ □     │
└──────┴────────────────┴──────┘
```

### 5.2 难度梯度参考

难度档用 schema 的三个枚举值：基础 / 中等 / 较难。比例按适用场景选：

```text
· 校内形成性（调进度）  ：基础 60% / 中等 30% / 较难 10%  → "6:3:1"
· 期末·中考模拟        ：基础 70% / 中等 20% / 较难 10%  → "7:2:1"
· 诊断性（找起点）      ：基础 80% / 中等 20% / 较难 0%   → "8:2:0"

必须在细目表首行写明本次用的是哪一档及理由，并写入
examBlueprints[].difficultyRatio。
```

### 5.3 时长测算

```text
不使用"单题时长 = 60-90 秒 × 难度系数"这类公式——
"难度系数"在测量学里指的是 P（得分率），不是可以拿来乘时间的倍数，
这个式子没有出处，也算不准。

可用的做法（按本班实际校准）：
① 沿用本地既有同类卷的总时长，按题型配比分配
② 老师自己完整做一遍，用**自己用时的 3-4 倍**作为学生用时的估计（经验值）
③ 拼卷后留 10-15% 的检查时间
④ 考后用实际交卷时间反过来校准下一次的估计

写入 examBlueprints[].durationMinutes 时填**老师确认过的实际值**，
不填公式算出来的数。
```

## 6. 第 5 步：拼卷定稿

### 6.1 拼卷原则

```text
原则 1：由易到难
  · 学员先做会的，再做难的
  · 增强信心

原则 2：同类集中
  · 选择-填空-解答-证明分层
  · 避免题型混排

原则 3：分值合理
  · 选择 2-3 分，填空 3-5 分
  · 解答 5-15 分

原则 4：留白充足
  · 给学员足够的答题空间
```

### 6.2 试卷结构样板

## 7. 第 6 步：考后统计与交接（讲评课不在本 SKILL 内设计）

### 7.1 本 SKILL 到哪里为止

```text
第 1 步：逐题 P/D 速览  ✅ 本 SKILL
  · 算出每道题的 P、D、flag，标出错误率 >30% 的题号
  · D<0 或 P 极低的题先复核题目本身（题干、答案、评分标准），
    这是命题质量问题，属于本 SKILL 的职责

第 2 步：知识点得分率  ✅ 本 SKILL
  · 按知识点汇总班级得分率，标出最低的 3 个

到这里，本 SKILL 的工作结束。下面三件事各有专门 SKILL：

❌ 错因归类（七类分析、抽答卷看步骤）
     → xiaozhi-teach-math-error-analyzer
❌ 讲评课编排（讲哪几题、多少分钟、变式训练、当堂巩固）
     → xiaozhi-teach-math-lesson-planner
❌ 个别辅导与重点关注名单
     → xiaozhi-teach-student-analyzer

理由：讲评要决定"为什么错、先讲什么、谁需要额外补"，
这三个判断都要看学生的实际书写与历次表现，不是一份卷子的统计量能给出的。
本 SKILL 硬做只会给出看着合理、其实没有依据的建议。
```

■ 班级：[化名] 班   实考 [N] 人
