# 周课表与课时台账模板

> 适用学段：小学中段 / 小学高段 / 初中 / 高中
> 配合 `xiaozhi-teach-schedule-manager` 使用。
> 完整 Prompt 逻辑请参阅 [`../SKILL.md`](../SKILL.md)。
> 课时长度与就寝时间参数见 `shared/grade-bands.md`；续费节点与 `xiaozhi-teach-renewal-report` 统一为已用 50% / 70%。

---

## 一、学员可上课时间段（`availability[]`）

时间冲突检测的**唯一依据**。每条写成 `{dayOfWeek, startTime, endTime}`，只记时间，不记原因。

```text
━━━━━━━━━━━━━━━━━━━━━━━━━━━
📅 可上课时间段 · [化名]
━━━━━━━━━━━━━━━━━━━━━━━━━━━
■ 时间段（最多 21 条）
  ① dayOfWeek [周三]  startTime [18:30]  endTime [20:00]
  ② dayOfWeek [周六]  startTime [09:00]  endTime [12:00]
  ③ dayOfWeek [    ]  startTime [     ]  endTime [     ]
  格式：dayOfWeek 取 周一…周日；时间为 24 小时制 HH:MM

■ 单次课时长：[N] 分钟
  参考 shared/grade-bands.md 三：校外一对一/小班常见 60 或 90 分钟；
  线上单次建议 ≤ 30-45 分钟。授课形式读 teacherProfile.deliveryChannels。

■ 建议的最晚结束时间（按学段，见 shared/grade-bands.md 一）
  小学中段 就寝 21:00 → 课程结束不晚于 20:00
  小学高段 就寝 21:20 → 课程结束不晚于 20:20
  初中     就寝 22:00 → 课程结束不晚于 21:00
  高中     就寝 23:00 → 课程结束不晚于 21:30
  以上为默认经验值，家庭作息优先。

■ 不写进来的东西
  ❌ "学校晚自习到 21:00"（写不可用即可，不写去向）
  ❌ "周三上钢琴课"（家庭安排，不入档案）
  ❌ "妈妈周日要加班"（家长信息，不入档案）
  这些时间直接不出现在 availability[] 里就是了。
━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

> ⚠️ 不要把时间信息写进 `learningPreferences[]`。那个字段记的是学习方式偏好（"喜欢先看例题"），不是时间。

## 二、老师时间矩阵

老师自己的时间不入学员卡，只在会话中使用。

```text
━━━━━━━━━━━━━━━━━━━━━━━━━━━
📅 老师时间矩阵 · [本周]
━━━━━━━━━━━━━━━━━━━━━━━━━━━
■ 老师固定不可用时间
  · 工作：[时间段]
  · 通勤：[时间段]
  · 个人事务：[时间段]

■ 老师可用课时
  周一：[N] 个课时位
  周二：[N] 个课时位
  ...
  周日：[N] 个课时位
  本周总可用：[N] 个课时位

■ 老师偏好（示例，按老师实际情况填）
  · 上午不排课
  · 晚上最后一节课的结束时间，按所带学员学段中最早的一档来定
    （见上表；带小学生就不排到 20:00 之后）
  · 周末集中排课
  · 线上课单次不超过 45 分钟
━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 三、周课表模板

```text
━━━━━━━━━━━━━━━━━━━━━━━━━━━
📅 周课表 · [本周日期范围]
━━━━━━━━━━━━━━━━━━━━━━━━━━━
        │ 周一   │ 周二   │ 周三   │ 周四   │ 周五   │ 周六   │ 周日
────────┼────────┼────────┼────────┼────────┼────────┼────────┼────────
上午 9:00│ 化名A  │ 休息   │ 化名C  │ 化名A  │ 休息   │ 化名E  │ 化名B
上午 10:30│ 化名D │ 化名A  │ 化名F  │ 化名D  │ 化名C  │ 化名E  │ 化名G
────────┼────────┼────────┼────────┼────────┼────────┼────────┼────────
下午 14:00│ 化名B  │ 化名D  │ 化名G  │ 休息   │ 化名F  │ 化名H  │ 化名A
下午 15:30│ 化名A  │ 化名E  │ 化名F  │ 化名C  │ 化名G  │ 化名H  │ 休息
────────┼────────┼────────┼────────┼────────┼────────┼────────┼────────
晚上 19:00│ 化名E  │ 化名F  │ 化名A  │ 化名D  │ 化名H  │ 休息   │ 休息
晚上 20:30│ 化名G  │ 化名C  │ 化名B  │ 化名F  │ 化名H  │ 休息   │ 休息
━━━━━━━━━━━━━━━━━━━━━━━━━━━
■ 课时统计
  · 本周总课时：[N] 课时
  · 已排：[N] 课时
  · 空闲位：[N] 个
━━━━━━━━━━━━━━━━━━━━━━━━━━━
注：20:30 这一排只适用于初中及以上学员。小学学员的课不排进这一行
    （按 shared/grade-bands.md 一的就寝时间倒推）。
```

### 3.1 课表生成三步走

```text
第 1 步：固定学员优先
  · 每周固定时间学员先排
  · 锁定本周的"硬骨架"

第 2 步：临时学员填空
  · 填空固定学员之间的空位
  · 优先安排学习节奏紧急的学员

第 3 步：留缓冲位
  · 留 1-2 个空位处理调课/补课
  · 不满课是健康的课表
```

## 四、冲突检测

### 4.1 冲突类型

```text
■ 老师时间冲突
  · 同时段 lessonSchedule[] 已有 status=scheduled/makeup 的课
    （按 startTime + durationMinutes 算区间，看是否重叠）
  · 同时段是老师登记的不可用时间

■ 学员时间冲突
  · 拟排时段不落在该学员任何一条 availability[] 内
    判据：同一 dayOfWeek 且 startTime ≤ 拟排开始，拟排结束 ≤ endTime
  · 该学员没有 availability[] 记录 → 不猜，先问一次并登记

■ 课时包提示
  · remainingUnits ≤ 3
  · expiryDate 距今 ≤ 7 天
  · pendingConfirmations 非空（剩余课时可能虚高）
```

### 4.2 冲突检测输出

```text
━━━━━━━━━━━━━━━━━━━━━━━━━━━
⚠️ 冲突检测报告 · [排课请求]
━━━━━━━━━━━━━━━━━━━━━━━━━━━
■ 排课请求
  学员：小A
  时间：[日期] [HH:MM-HH:MM]
  时长：[N] 分钟

■ 检测结果
  老师时间：□冲突 □可用
    · 冲突对象：[同时段已排的课节 lessonId]
  学员时间：□冲突 □可用
    · 判据：availability[] 中 [周三 18:30-20:00]，
      拟排 [周三 20:00-21:30] 超出区间
    · 或：该学员尚无 availability[] 记录，需先登记
  课时包：□正常 □需提示
    · 剩余：[N] 课时（未含 [N] 条待确认）
    · 到期：[日期]（[N] 天后）

■ 建议
  · 若冲突：给 1-3 个落在 availability[] 内的候选时段，由老师选
  · 若课时不足：先问老师"照排 / 先跟家长确认 / 暂不排"
  · 不主动提出退款、折算或催缴
━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 六、课时包台账

```text
━━━━━━━━━━━━━━━━━━━━━━━━━━━
💰 课时包台账 · [化名]
━━━━━━━━━━━━━━━━━━━━━━━━━━━
■ 课时包信息
  类型：[N 课时小包/中包/学期包]
  生效：[日期]
  到期：[日期]
  续费节点预警：[日期]（[N] 天前）

■ 课时消耗
  初始：[N] 课时
  已消耗：[N] 课时
  剩余：[N] 课时（[N]%）
  状态：□充足 □预警 □耗尽

■ 待确认条目（pendingConfirmations）
  · [lessonId]（[生成时间]）：[N] 课时 —— 等老师确认
  · 确认前不计入已消耗；剩余课时展示一律注明"未含 [N] 条待确认"

■ 消耗历史（老师确认后才记入）
  · [日期] [lessonId]：-1 → 剩余 [N]
  · [日期] [lessonId]：-1 → 剩余 [N]

■ 续费记录
  · 第 1 次续费：[日期] +[N] 课时
  · 第 2 次续费：[日期] +[N] 课时

■ 提示条件（置 renewalAttention，提示对象是老师本人）
  · remainingUnits ≤ 3
  · expiryDate 距今 ≤ 7 天
━━━━━━━━━━━━━━━━━━━━━━━━━━━
注：本台账只记课时数量，不记金额、单价、收款、欠费、退费。
```

## 七、课时提示规则

```text
■ 触发条件（置 coursePackageLedger[].renewalAttention）
  · remainingUnits ≤ 3
  · expiryDate 距今 ≤ 7 天

■ 提示动作（说给老师听，不推送家长）
  · 陈述事实：「小A 还剩 3 课时，课时包 [日期] 到期，
    另有 1 条待确认（确认后剩 2 课时）。」
  · 不催单、不制造紧迫感、不替老师决定要不要续

■ 续费节点口径
  · 已用 50% / 70%
    与 xiaozhi-teach-renewal-report、xiaozhi-teach-student-intake
    同一套，本文件不另设节点

■ 要和家长谈时
  · 话术起草交 xiaozhi-teach-parent-communication
  · 起草前查 studentCards[].consent 的 parentCommunicationAllowed
  · 发送由老师本人完成
```

### 7.1 课时异常处理

```text
■ 剩余课时不足却又要排课
  · 生成待确认提示：「小A 只剩 1 课时，这节课排下去会超出课时包。
    照排 / 先跟家长确认 / 暂不排？」
  · 老师选"照排"才写入课表；不代做"允许透支 N 课时"的决定

■ 学员请假不补课
  · 课时不扣；是否另行约定由老师与家长商定
  · 不涉及金额结算

■ 老师取消
  · 课时不扣
  · 生成待确认的补课建议（1-3 个落在 availability[] 内的候选时段），
    老师选定并与家长确认后写入课表
  · 不涉及退款：课时包只记数量，金额相关请用独立记账工具
```

## 八、特殊场景处理

### 8.1 寒暑假排课

```text
■ 寒暑假特殊安排
  · 增加排课密度（每周 N+2 课时）
  · 提前 2 周确认学员时间
  · 寒暑假专属课时包

■ 节奏建议
  · 假期前 1 周：学期收尾 + 假期规划
  · 假期中：高频复习 + 预习
  · 假期后 1 周：节奏调整
```

### 8.2 考试期排课

```text
■ 考前 2 周
  · 减少新课
  · 增加复习/测评
  · 学员优先完成学校作业

■ 考试期间
  · 暂停新课
  · 答疑 + 心理支持
  · 考后复盘

■ 考后 1 周
  · 复盘考试结果
  · 调整下阶段计划
```

### 8.3 学员请假多

```text
■ 触发条件
  · 1 个月内请假 ≥ 3 次
  · 连续 2 周请假

■ 应对
  · 主动了解原因
  · 评估是否需要调整节奏
  · 考虑续费意愿
```

## 九、自检清单

每次输出排课/课时管理前，AI 必须自检：

- [ ] 时间冲突是否只用 availability[] 判定（没用 learningPreferences）
- [ ] 冲突检测是否覆盖三类（老师时间/学员 availability/课时包）
- [ ] 排课结果是否等老师确认后才写入
- [ ] 补课是否给的是候选时段而不是直接排进去
- [ ] 剩余课时展示是否注明"未含 N 条待确认"
- [ ] 课时提示是否只陈述事实、未催单
- [ ] 是否避免了退款、折算、金额相关表述
- [ ] 结束时间是否符合该学员学段的就寝倒推（shared/grade-bands.md 一）
- [ ] 补课/请假/调课是否都有登记，调课是否双方确认
- [ ] 是否使用化名
- [ ] 是否避开了高敏信息（住址/家长职业/学校班级/联系方式）
- [ ] availability[] 是否只记时间、没记原因

---

> **使用提示**：建议老师在每周日下午排下一周的课表；寒暑假提前 2 周排；考前一月切换到"考试期"排课模式。
