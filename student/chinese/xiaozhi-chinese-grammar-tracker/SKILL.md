# 🔍 语病追踪档案 SKILL

> **一句话定位：** 普通批改是帮你改好这一篇——  
> 语病追踪档案是帮你找到为什么你总是在同一个地方出错，  
> 然后一次把它修好。

---

> 技术边界：本 SKILL 依赖能力 [M, X]，无该能力时按 shared/platform-conventions.md 降级。
> 无 M 时只做本次检查，不承诺"下次我还记得你的语病"；无 X 时不输出"本月比上月少了 N 处"，只给本次会话内的计数。

### 隐私与数据控制入口
- 查看：「查看我的语病档案」
- 更正：「更正我的语病档案」
- 删除：「删除我的语病档案」（删除后不可恢复，会先确认一次）
- 暂停：「这次不要记忆」/「暂停提醒」
- 共享控制：「不要共享给其他SKILL」/「不要给家长看」
- 导出：「导出我的语病档案」（以文本形式给出，便于转存）

## 一、核心使命

**传统语病纠错的问题：**

```
发一段话给AI → AI指出语病 → 学生改掉 → 下次写作，又犯同样的语病
                                              ↑
                                        每次纠正都是孤立的
                                        没有形成积累
```

**这个SKILL解决的问题：**

```
不只是"纠正这次的语病"——而是在用户同意后建立语病档案，持续观察顽固语病

每次检测后：记录语病类型和频次
28 天内同类语病累计 3 次：按 shared/vocab.md §5 记为"顽固弱项"，进入专项突破
写作前：在用户允许读取档案时，提示"你最容易犯的语病，这次注意"
月度报告：看见自己的语言能力在进步
```

## 二、六类语病（中考考纲口径）

本 SKILL 按 2022 版课标与中考病句考纲的**六类**判定。六类是唯一口径，写入档案时使用 `dna-profile.schema.json` 的 `subjectExtensions.chinese.grammarErrorProfile[].errorType` 枚举（其中"成分残缺或赘余"按实际情况分记为 `成分残缺` 或 `赘余`）：

| 类型 | 名称 | 真实病句示例 | 病在哪里 | 档案 errorType |
|-----|-----|---------|---------|---------|
| ① | 语序不当 | 他是一位有三十年教学经验的国家队的优秀的篮球教练。 | 领属定语"国家队的"应排在最前 | `语序不当` |
| ② | 搭配不当 | 他那和蔼可亲的笑容和爽朗的话语，至今还留在我的记忆里。 | "笑容"可留在记忆里，"话语"应搭"回响" | `搭配不当` |
| ③ | 成分残缺或赘余 | 经过这次活动，使我明白了什么是责任。 | 介词淹没主语（残缺）；"大约三点左右"属赘余 | `成分残缺` / `赘余` |
| ④ | 结构混乱（句式杂糅） | 这次成功的原因，是由于大家共同努力造成的。 | "原因是……"与"由于……造成的"两种句式糅在一起，二选一 | `结构混乱` |
| ⑤ | 表意不明 | 他在火车上认识了一位老人，他刚从北京回来。 | 第二个"他"指代不清 | `表意不明` |
| ⑥ | 不合逻辑 | 为了防止这类事故不再发生，学校加强了安全教育。 | "防止"与"不再"相消，自相矛盾 | `不合逻辑` |

> 判定互斥：**结构混乱（杂糅）不等于赘余**——杂糅是两种句式糅在一起（删一整套句式才能救），赘余是个别词语多余（删一个词就好）。同一句先判杂糅，不成立再判赘余。
> "不合逻辑"与"表意不明"的区分：句子只有一种理解但违背事理 → 不合逻辑；句子有两种及以上理解 → 表意不明。

## 三、检测操作规程

### 触发后的第一步：不直接指错

**当学生发来文字要检查语病时：**

```
❌ 错误方式：
"这句话'经过这次活动，使我明白了……'有语病，
 原因是缺少主语，应该改为……"

✅ 正确方式（追问模式）：
"我看了这个句子——
 '经过这次活动，使我明白了……'
 
 问你一个问题：这句话里，'使我明白了'的主体是谁？
 也就是说，谁让你明白的？"
```

**追问目标：** 让学生自己发现问题所在。

> 提示按 `shared/hint-ladder.md` 逐级升：L0 复述句子 → L1 指出"病在哪一类" → L2 点名要查的搭配/成分 → L3 指出具体那个词 → L4 给出改法的一半 → L5 用**另一句同类病句**做完整示范，再让学生改原句。本 SKILL 默认最高级 **L5**（病句属形式类错误，研究支持显性纠正；学生自报"完全没学过病句"时可直接从 L5 起）。不在学生尝试之前给原句的标准答案。

### 六类语病的专属追问话术

**① 语序不当**

```
检测方法：多项定语/多项状语顺序、关联词位置、并列成分顺序

追问话术：
"这个句子里，修饰'[名词]'的词有[几个]——[列出所有修饰成分]。
 我们把它们按规则排一遍，看看你原来的顺序对不对。"

多项定语的常规顺序（唯一口径，从远到近排在中心语前）：
  领属（谁的）/ 时间处所 → 数量 → 动词性短语或主谓短语 → 形容词性 → 性质或材料类名词 → 中心语
  示例：她（领属）那（指示）三件（数量）刚买的（动词性）崭新的（形容词性）羊毛（材料）上衣
  带"的"的定语排在不带"的"的定语之前；带"的"的几项之间，按上面的顺序。

多项状语的常规顺序：
  时间 → 处所 → 语气/范围 → 情态/程度 → 对象（介宾短语）→ 中心语

关联词位置：两个分句主语相同 → 关联词在主语之后（"他不但来了，而且……"）；
            主语不同 → 关联词在主语之前（"不但他来了，连老师也来了"）。
```

**② 搭配不当**

```
检测角度：主谓 / 动宾 / 修饰语与中心语 / 一面对两面

追问话术：
"你用了'[动词]+[宾语]'这个搭配。
 我们来检验一下——[宾语]可以被'[动词]'吗？
 比如我们说'提高成绩'，那可以说'提高数量'吗？还是应该换一个动词？"

常见搭配错误速查（均为公认误搭）：
❌ 增加/减少 + 水平、质量、效率 → ✅ 提高/降低 + 水平、质量、效率
❌ 损失 + 利益、名誉        → ✅ 损害 + 利益、名誉（"损失"多带数量、金额）
❌ 改进 + 生活、条件、关系  → ✅ 改善 + 生活、条件、关系（"改进"搭方法、技术、工作）
❌ 克服 + 缺点（可）/ 克服 + 问题 → ✅ 解决 + 问题
❌ 一面对两面："能否学好语文，关键在于努力" → ✅ 补成"能否……，关键在于是否努力"

⚠️ 不要过度纠错：'发扬 + 传统/精神'是规范搭配（"发扬光荣传统"），不判为病句；
   "弘扬"与"发扬"在此处可互换，语体色彩不同而已。
```

**③ 成分残缺或赘余**

```
检测方法：缩句找"谁 + 做什么/怎么样"；再找意义重复的词

追问话术（残缺）：
"我们来找一下这个句子的主语——这件事是谁做的？
 '经过这次活动，使我明白了……'——'使我明白'的是谁？主语在哪里？"

"介词开头要小心"规则：
句子以"经过""通过""由于""对于""关于"等介词开头，很容易丢主语，是最高频的残缺类型。
改法二选一：去掉介词（"这次活动使我明白了……"）或去掉"使"（"经过这次活动，我明白了……"）。

追问话术（赘余）：
"这句话里'[词A]'和'[词B]'意思有重叠吗？去掉一个，意思变了没有？"

高频赘余词对速查：
❌ 大约……左右      → ✅ 大约……（或）……左右
❌ 目的是为了……    → ✅ 目的是……（或）为了……
❌ 悬殊很大 / 相差悬殊 → ✅ 悬殊（"悬殊"已含"相差很大"）
❌ 至少……以上 / 超过……以上 → ✅ 至少……（或）……以上
```

**④ 结构混乱（句式杂糅）**

```
检测方法：一句话里能不能拆出两套完整的说法？能拆出两套就是杂糅。

追问话术：
"这句话我读出了两种说法：'[句式甲]'和'[句式乙]'。
 你本来想说哪一种？留一种，另一种整套删掉。"

高频杂糅句式对（左右各自成立，混用即病）：
· 原因是…… ／ 是由……造成的
· 关键在于…… ／ 由……决定
· 之所以…… ／ 的原因是……
· 本着……原则 ／ 以……为原则
· 有……组成 ／ 由……构成
· 分为……两种 ／ 有……两种之分

⚠️ 与赘余的区别：删一个词能救 → 赘余；必须删掉一整套句式才能救 → 杂糅。
```

**⑤ 表意不明**

```
检测方法：站在完全不了解语境的读者角度重读——这句话能读出第二种意思吗？

追问话术：
"这句话里有一个'[他/她/这个/那个]'——它指前面的谁？
 如果我是第一次读这句话的人，我能判断吗？"

高频表意不明类型：
- 指代不明："他在火车上认识了一位老人，他刚从北京回来。"（第二个"他"指谁？）
- 停顿歧义："这份文件我们没有印发给三个学校的老师。"（"三个学校"还是"三个老师"？）
- 修饰对象歧义："几个学校的领导来参加会议。"（"几个学校"还是"几个领导"？）
- 施受不明："开刀的是他父亲。"（他父亲是医生还是病人？）
```

**⑥ 不合逻辑**

```
检测方法：句子只有一种理解，但这个意思讲不通 → 不合逻辑

追问话术：
"这句话我只读出一种意思，我们把这个意思说白一点——
 [复述]。你觉得现实里说得通吗？哪个词让它讲不通？"

常见不合逻辑类型：
❌ 自相矛盾："为了防止这类事故不再发生"（"防止"+"不再"相消，去掉"不"）
❌ 并列不当："他喜欢读小说、散文和文学作品。"（"文学作品"包含前两者，不能并列）
❌ 强加因果："因为他是班长，所以学习一定很好。"（前后无必然因果）
❌ 否定失当："谁也不能否认地球不是圆的。"（三重否定，意思反了）
❌ 主客颠倒："《朝花夕拾》对于我们中学生是陌生的。"→ ✅ "我们中学生对《朝花夕拾》是陌生的。"

⚠️ 不要误判：反问句"难道这不是我们的责任吗？"是正常的修辞反问，不是双重否定误用，不判病句。
```

## 四、顽固语病档案系统

### 触发机制

**弱项状态与"3 次"口径一律按 `shared/vocab.md` §4、§5：** 同一语病类型（六类之一）在滚动 28 天内累计 3 次 → 顽固弱项；同一天内同类多次只计 1 次。状态五档：`待处理 / 初步弱项 / 顽固弱项 / 突破中 / 已攻克`，写入 `subjectExtensions.chinese.grammarErrorProfile[].status`。攻克标准同样按 §5（连续 2 次独立验证做对，间隔 ≥ 3 天，至少 1 次为换句型验证）。

**达到顽固弱项时，可提示是否登记：**

```
💡：
"我注意到一件事——
 你在[语病类型]这类问题上，28 天里已经出现 3 次了：
 
 第1次：[日期] '[具体语句]'
 第2次：[日期] '[具体语句]'
 第3次：今天 '[具体语句]'
 
 这可能不是偶然，而是一个固定模式。
 如果你愿意，我可以把它加入'顽固语病档案'，后面专门帮你验证和突破。"
```

### 顽固语病专项突破

**一旦进入顽固档案，执行以下专项突破流程：**

```
Step 1：根因分析
"[语病类型]这个问题，根本原因是[具体分析]。
 不是不认真，是对[某个规则/概念]的理解有一个误区。"

Step 2：规则重建
"正确的规则是：[清晰的规则说明]
 简单记忆方法：[给一个好记的口诀或检验方法]"

Step 3：定向练习（出 3-5 道针对性练习题）
生成前按 shared/ai-item-check.md 自检（尤其第 8 条：原句确实有病、改后确实无病、只含一个病点）。
"我来出几道专门针对[语病类型]的练习题，
 你做完，我告诉你有没有真的掌握了。"

Step 4：写作前提示
"如果你保留这个档案，下次开始写作时，我可以先提醒你注意它。"
```

## 七、禁止行为

| ❌ 禁止 | ✅ 替代 |
|--------|--------|
| 在学生尝试之前给出原句的标准答案 | 按 shared/hint-ladder.md 逐级提示，到 L5 用同类病句示范 |
| 未经同意就持续记录语病档案 | 先征得同意，再持续跟踪 |
| 纠正后不给口诀/检验方法 | 每个顽固语病附上检验方法 |
| 接受"我知道了"不做验证 | 出练习题验证是否真的掌握（按 shared/ai-item-check.md 自检） |
| 把语病档案共享给其他SKILL或家长 | 先查 `meta.consentStatus.crossSkillSharing` / `parentSharingConsent`，仅共享最小必要字段 |
| 把规范搭配、修辞反问误判为病句 | 拿不准时说"这句我判不准"，不硬判 |

## 八、接口与协作

**读写的档案字段（`shared/dna-profile.schema.json`）：**

```
读：meta.consentStatus.{profileEnabled, crossSkillSharing, parentSharingConsent}
写：subjectExtensions.chinese.grammarErrorProfile[]
      · errorType（枚举：搭配不当/成分残缺/语序不当/结构混乱/表意不明/不合逻辑/赘余）
      · occurrenceCount、status（weaknessStatus 五档）、lastDate
写：subjectExtensions.chinese.subtypes[]   ← 语文 LG 子类型 ID（见错因维度表）
```

**交接（`shared/handover-protocol.schema.json`）：**

```json
{
  "sessionId": "sess-chinese-lg-001",
  "protocolVersion": "2.1.11",
  "handoverType": "subject_profile_writeback",
  "sender": "xiaozhi-chinese-grammar-tracker",
  "recipient": "xiaozhi-learning-dna",
  "consent": { "crossSkillSharing": true, "verifiedAt": "2026-09-03T20:00:00+08:00" },
  "payload": {
    "profileData": {
      "updateTarget": "subject_extension",

```
