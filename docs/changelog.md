## 未发布 — 回归测试集（evals/）

审计报告阶段 3 的第一项。v2.1.1–2.1.3 三个版本追的 ClawHub 判定，根因全是“文件之间互相矛盾”——SKILL.md 说不归档、references 说归档，每份文件单看都合法，18 项静态校验一项也抓不到。这一层只能靠把话说进去看它怎么答。

- `evals/<skill>.json`：58 份，共 394 条用例（触发 106 / 不触发 123 / 降级 70 / 授权 62 / 危机 33）。`must` / `must_not` 写行为不写台词。
- `scripts/check-evals.mjs`（进 `npm run check`，E1–E7）：用例文件过 schema；每个 SKILL 至少 1 触发 + 1 不触发；声明了能力代号的必须有降级用例且 `missing` 不越界；持有长期数据的必须有授权用例；会读到情绪文本的必须有危机用例；`route_to` 与授权字段名必须存在。P1 / S1 集的判定与 `check-skills.mjs` 用同一组正则。
- `scripts/run-evals.mjs`（手动，`npm run evals:run`）：把 SKILL.md + 随包 shared/ 喂给模型逐条对话，判卷模型对照期望打分，报告在 `evals/report/`。不进门禁——要 API key，且结果非确定。
- 用例不进发布包：它是仓库的测试资产。

写用例时顺带记下的、值得盯的回归点都放在各文件的 `notes` 里（例如哪个邻居最容易抢触发、哪条历史缺陷最容易回来）。

### 示例题验算从“声明”变成“检查”（阶段 3 第二项）

此前 A1 只查 references 顶部有没有一行“示例题验算：日期”，日期本身不检查任何东西。现在两道：

- **A2（`check-skills.mjs`）**：验算日期不得早于文件最后一次实质提交（git，纯升版提交不算）。上线即抓到 2 份——`exam-design-process.md` 与 `model-examples.md` 在 09-04 的安全整改中改过却没重新验算。前者只改了边界措辞、无数值示例，后者逐条核算后写成断言，日期均已更新。
- **`scripts/verify-examples.mjs`**：references 里可写 ```verify``` 块（`claim` / `expr` / `expect`），CI 逐条求值。`expr` 只含 Math 与字面量。首批 11 条断言覆盖审计报告点名过的病题：184 分题无整数解、一次函数不过第二象限的旧版无解、“直线与 x 轴围成三角形”不成题、增长率的错误模型 a(1+2x)，以及物理教案的平均速度/过桥/雷声/杠杆算例。题目一改，断言就红。
- `shared/ai-item-check.md` §三同步改写，随包分发。

剩下 16 份有验算声明但还没有断言的文件只给警告（X3），断言是逐题补的活，不一次做完。

A2 顺带补了一条：**文件有未提交改动且声明日期早于今天**也报错。否则本地 `npm run check` 只看 git 历史，改完没提交时是绿的，提交后下一次才红——先绿后红是最容易被忽略的信号。

### frontmatter 收敛到 Agent Skills 官方字段（阶段 3 第三项）

58 个 SKILL.md 的顶层现在只有官方字段 `name` / `description` / `license` / `compatibility` / `metadata`（部分老师端技能另有平台加载字段 `id` / `min_platform_version` / `max_round_limit`，按 `shared/platform-conventions.md §六` 保留）。本库自有的 `display_name` / `version` / `author` / `category` / `grade_bands` / `tags` / `depends_on` 全部移入 `metadata:` 块；`license: MIT` 补为顶层字段。

- `scripts/check-skills.mjs` F1 改为：顶层出现非官方、非平台字段即失败；`metadata` 七个字段齐全且 `version` 等于 `package.json`。
- 发布打包（`stage.py`）把 `metadata` 投影回顶层——SkillHub 的 frontmatter 解析器只认顶层 `key: value`，ClawHub 也不读嵌套块。市场上看到的 frontmatter 与 v2.1.3 完全相同，只是仓库里的形态变了。
- 文档与 `tools/xiaozhi-skill-creator` 里教的 frontmatter 写法同步更新。

这一项不改任何技能行为，不单独发版；随下一次内容发布一起上架。

### 文档与源码同步机制（阶段 3 第四项）

原条目写的是“changelog 由脚本从 frontmatter 生成”。做的时候发现 changelog 与 README / architecture 里的技能描述都是人写的判断，不该由脚本生成；能从 frontmatter 推出来的只有显示名、目录、学段、依赖、数量。所以拆成两件事：**能推的生成，手写的核对**。

- `docs/skills-index.md`：`npm run docs:gen` 从 58 个 SKILL.md 的 `metadata` 生成，勿手改。
- `scripts/gen-docs.mjs --check`（进 `npm run check`，D2–D5）：索引不落后于 frontmatter；README / architecture 技能表的显示名、目录、学段列与 frontmatter 一致，改名后的残留显示名报错；“全库 N 个 SKILL / N 份 references”等数量声明与实际一致；**安装指南的顺序不违反 `metadata.depends_on`**。

D5 上线即抓到 8 处：安装指南把教案设计器排在学情分析师前、学情分析师排在测评设计师前、独立教师工作台排在它聚合的三个技能前——都是审计报告第 47 条“安装顺序与 depends_on 冲突”的同类问题，改了依赖没改指南。已按依赖重排，并在指南里写明为什么这样排。

### 关于扫描判定的一点记录

## v2.1.1 — 安全边界整改

起因是 ClawHub 上架扫描（ClawScan + SkillSpector + 静态分析）对 v2.1.0 的判定：57 个技能中 44 个 clean、13 个 suspicious。三类根因，全部收敛在本版。

### 一、地域适用性（`environment_proportionality`，命中 9 个技能）

此前全库把 110/120 当作通用紧急电话直接输出，在中国大陆以外是错误且危险的指引。现改为**先确认地区再给号码**：

- `shared/crisis-exception.md` 新增“适用地域”一节：不确定地区时先问一句，问清前只做“联系身边信任的成年人”这一条通用引导；确认在中国大陆才给 110/120、12355、希望24热线；其他地区一律改为当地紧急电话与当地求助资源。
- `shared/platform-conventions.md` 新增“〇、适用范围与地域”：本库按中国大陆中文 K12 场景设计，跨地区部署前需先完成求助渠道本地化、学科口径核对、未成年人数据法规核对。
- `learning-dna/references/crisis-referral-protocol.md` 的渠道节拆为「中国大陆 / 中国大陆以外」两套。
- **28 个 SKILL.md 的危机例外片段**统一换成地域感知口径，全库不再有硬编码的通用 110/120。

### 二、职责越界（`instruction_scope` / `purpose_capability`）

扫描器判定部分技能的正文或 references 指示了超出其声明职责的动作。按“声明边界 + 转交具体技能”整改：

| 技能 | 交出去的职责 |
|---|---|
| `teach-math-exam-designer` | 错因分析、A/B/C 分层、补救干预、家长沟通四项转交；只做命题蓝图、选题、题目统计与经确认的写回 |
| `teach-physics-lesson-planner` | 器材清单、操作步骤、安全组织流程转交 `physics-experiment-coach`；教案只排“实验位” |
| `teach-parent-communication` | 不再改写学员档案 |
| `teach-review-planner` | 读取侧最小化，触发歧义时先澄清 |

同时修掉一处**跨技能矛盾**：`student-analyzer` 自称 `weaknessRank` / `studentTiers` 唯一写入方，但 `math-error-analyzer`、`chinese-writing-guide`、`exam-designer` 也把它们列在写入块里。现统一为：`studentTiers`（A/B/C 分层）由 `student-analyzer` 唯一维护，其余只读；`weaknessRank` 允许学科技能补本学科条目，但 **`stubbornCount` 只由 `student-analyzer` 累加**——两处都累加会把 `shared/vocab.md §5` 的“近 4 次错 3 次”判错。

### 三、持久化与授权（`persistence_privilege`）

- 写入长期档案 / 工作空间前必须有显式确认，未确认的内容只存在于当前会话；`teach-review-planner` 的 `reviewPlans` 写入加“三道门”（老师确认 + 化名 + 无分数无排名）。
- `shared/vocab.md §8` 规则 3 改写：学生与家长共用一个 IM 会话时，**确认说话人之前进入受限模式**——不读长期档案、不写记录、不执行删除、不变更授权位、不输出家长版内容。此前的“无法确认时按学生本人处理”等于用未经核实的身份读写未成年人档案。
- 独立教师工作空间 `retentionUntil` 明确：已报名学员结课后 6 个月，未报名试听学员试听日 + 90 天；到期提示老师确认，不自动删除、不自动续期。

### 四、实验安全

`experiment-types.md` 的 `safetyLevel` 三档定义补**激光专项**：此前只覆盖 220 V 与化学品，激光笔完全缺位，而“探究光的反射规律”被列为低档。现新增判定分支（用激光笔即为中档）与专项处置——核实功率标识、光路压桌面以下、严禁射向眼睛或反射面、老师操作、优先用普通光源替代。物理教案技能的实验条目由 4 个补到 10 个全部标注 `safetyLevel`。

### 未处理

合规项（双减适用范围、课时包与优惠、分班用语、家长群与作业时长、月考与选拔性考试用语）按要求本轮仍不处理。

## v2.1.0 — 单一事实源与内容审校

本次是一轮系统性整改，起因是 [评估报告 2026-09](review-2026-09.md) 指出的三层问题：学科内容未经教研审校、跨 SKILL 协作停留在纸面协议、学段适配缺失。整改分基础设施、内容修正、文档三部分。

### 一、建立单一事实源（新增 `shared/`）

此前术语、阈值、降级规则散落在 58 个 SKILL 各自的正文里，同一概念存在多套定义。现全部收敛：

| 新增文件 | 解决的问题 |
|---|---|
| `shared/vocab.md` | 错因分类此前学生端 4 套、老师端 3 套并存；弱项状态 4 套；掌握度学生三档与老师五档无映射；"3 次顽固"有五种口径 |
| `shared/platform-conventions.md` | 58 个 SKILL 各自复述一遍平台机制；20 个依赖跨会话记忆的 SKILL 无降级路径 |
| `shared/crisis-exception.md` | 危机转介协议此前只被 2 个 SKILL 引用 |
| `shared/hint-ladder.md` | "永不给答案"绝对禁令与散落各处的泄题分支并存，学生多次卡住后无出口 |
| `shared/ai-item-check.md` | 全域即兴出题无自解验算，references 中已发现多道无解或不成题的示例 |
| `shared/grade-bands.md` | 声称适用 7-16 岁，实际 30/58 个 SKILL 无任何学段词 |

### 二、数据契约

| Schema | 变化 |
|---|---|
| 学习DNA | 授权位增加同意主体、学段、监护人要求、家长共享、情绪共享、教师写回、授权时间；新增四科扩展档案 `subjectExtensions`、五类通用扩展 `extensions`、安全处置记录 `safetyRecord`；错因与状态改用共享定义；概念图谱成为唯一图谱结构，旧的知识积累树标记弃用 |
| 交接协议 | 交接类型从 3 种扩到 **7 种**（补深度分析回写、学科档案回写、提醒入队、教师写回）；收发方枚举从 5 个扩到**全库 57 个**；新增授权位快照且为必填；情绪写入与教师写回改为 schema 硬校验 |
| 独立教师工作空间 | 补齐悬空字段：课后记录日期、逐知识点掌握、课堂反应、课时到期日与待确认条目、作业逾期天数、沟通渠道、学员状态与可用时段、资源的 AI 生成与验算标记 |
| 班级教学工作空间 | **新建**。此前老师通用与学科端 18 个 SKILL 的接口路径全部是虚构的点路径，互相读写对不上 |

示例数据从 1 份增加到 **8 份**，全部纳入校验。

### 三、打包自包含（`shared/` 随包分发）

SKILL 正文有 707 处引用 `shared/` 的共享约定，路径相对仓库根。实测技能市场的包只含 `SKILL.md` + `references/`，不含 `shared/`，因此单技能安装后这些引用会全部断开。

现在每个 SKILL 目录下都同步了一份 `shared/` 副本（58 × 6 = 348 个文件），使 `shared/vocab.md` 这类路径在整库使用与单技能安装两种场景下都能解析。副本由 `npm run sync:shared` 从仓库根生成，带"请勿直接编辑"横幅，并由 `npm run check` 校验与源逐字节一致。

跨技能引用的契约与参考资料同样按需分发到引用方的 `shared/` 下，共 13 类、124 份副本：四份数据契约 schema、三份交接示例、两份学科错因维度表、四份参考资料，以及分发给全部 58 个技能的危机转介协议（`crisis-exception.md` 在每个包里都指向它）。源文件仍留在归属技能里，归属技能不重复复制。

同时把 79 处 `../其他技能/…` 与仓库根相对路径改写为技能内路径，并清理了 `shared/vocab.md`、`shared/crisis-exception.md` 源文件里会随副本扩散到 58 个包的仓库路径。

对全部 58 个技能做了单技能安装模拟：单独取出任一技能目录后，其 `SKILL.md` 与 `shared/` 副本中的文件引用**全部可解析，零断链**。单包体积平均 131 KB。

### 四、校验体系

`scripts/check-references.mjs` 此前只检查文件是否存在，导致"改了一处、同类问题在别处照旧"反复发生。新增 `scripts/check-skills.mjs`（14 类内容级检查）、`scripts/validate-schemas.mjs` 与 `scripts/sync-shared.mjs --check`，接入 `npm run check`。

首次运行基线为 482 项问题，整改后归零。

### 五、结构调整

- **打破 6 组循环依赖**：数学与物理的解题教练/错误 DNA/错题本互指共 4 组，独立教师包 4 组（工作台与上游互指、家长沟通与续课报告互指）
- **独立教师包解耦**：课后记录与试听建档改为零依赖，整包可脱离老师通用包独立安装
- **SKILL 创建教练移出学生包** 至 `tools/`：投喂 PDF、写四层提示词、多轮热身不是 K12 学生的学习任务
- frontmatter 统一：版本号从 6 种归一；`depends_on` 从逗号字符串改为 YAML 列表（此前 36/58 会被解析成单个字符串）；新增 `grade_bands`；19 个 description 中的硬命令词与营销句清除

### 六、学科内容修正

本轮确认并修正 **26 处会直接教错的内容**。

**数学**：`1/x=2` 被当作一元一次方程示范；"任何三角形复制拼成矩形"（应为平行四边形）；一次函数不过第二象限的示例题无解；直线与单轴"围成三角形"不成题；变式样板 184 分无整数解；鸡兔同笼抬脚法用答案推答案；"简单增长"公式恰好合法化中考高频错误 a(1+2x)；射击命中率被当作理论概率；圆心角表述混入弧度、整式通分、函数零点、区间等术语。

**物理**：老师端三个 SKILL 的样板题、模型库、实验类型整体是高中内容，已全部重写为初中题型；小灯泡电阻取平均值与非线性数据拟合成正比（中考明确禁止）；内接外接误差方向写反；"大卡车质量大惯性大所以刹不住"这一典型迷思被当作正确直觉教授；帕斯卡原理用挤牙膏类比；凸透镜物远成像结论错误；标准大气压写成"1kg 的力"；串联电路出现"支路电流"；正确的除以 3.6 被标为错误。

**英语**：定语从句错因归结为"地点先行词用 where"，植入中考高频陷阱；卷面百分比直接映射欧洲语言共同参考框架等级，初二样板被标为接近 B2；重述式纠正的示范本身用第一人称且追问已答信息；用拼音给 th 音注音，恰好强化口语教练列为头号弱项的替代音；听力生词密度 10-15% 远超可理解输入阈值；语速 160 词每分钟超中考口径。

**语文**：三例正确句被列为病句；"何以"归为介词结构后置（应为宾语前置）；"吾师道也"活用归错；作文评分三套分制并存且按段数、修辞条数、高级词个数计分；把"读懂文章说感受"和"有感情朗读"定为错误做法，与课标思辨性阅读及中考按要点给分的事实相悖。

### 七、教学法与流程

- **提示阶梯**替代绝对禁令，各 SKILL 声明默认上限；到达上限后用同型例题或讲解加同类题收尾
- **CLAW 内部化**：不再要求初中生手打四行结构化提示词，改为只回答"你试到哪一步"
- **流程压缩**：数学状态机合并重复出题环节，五问链改为可选且与四步法互斥；错题本新增快速记录模式；各流程加轮次预算与"两轮无回复即收尾"
- **提醒预算**：改为队列加每日一条合并摘要，最多一条即时；免打扰按学段；连续三条无回应即暂停（原"每周一次持续唤醒"违反免打扰基线）
- **老师端测量学**：补上区分度的分组定义与信度，纠正"区分度低于 0.2 等于全对或全错"，基础题不再强求高区分度；能力层级统一课标四级并给出对照表；难度比例按测评场景区分
- **分层依据改为课前可得**：从"当节课目标达成率"（课后数据）改为近三次测评得分率
- **复习补上间隔与交叉练习**：1/3/7/14 天回看排期与易混知识点混排
- **老师端错因录入减负**：改为错误率超过 30% 才做细分加抽样，其余用四维

### 八、未成年人数据与安全

- 授权分主体与学段，小学各段必须监护人同意；学生与家长共用会话时先确认说话人
- 家长可见内容双门控：学习摘要与情绪内容分别授权
- 危机例外接入费曼熔断、学科焦虑流程、家长输出、倾诉入口、模板库
- 每个持有数据的 SKILL 补齐六项控制入口（新增导出）
- 建档不再收集家长联系方式与紧急联系人
- 删除"预期提分"字段、"治愈焦虑""感觉就会消失"等承诺，以及一处虚构的疗效对比数据
- 删除"思维天花板""天赋""连续 100 天"等固定型或平台黏性表述
