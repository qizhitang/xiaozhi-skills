## v2.1.9 — 按证据修九处真矛盾；协议补两条授权规则；副本裁到自洽

2.1.8 的判定是 **32 clean / 26 suspicious**（2.1.7 为 35 / 23）：转好 3、变差 6、不变 20。这轮最要紧的不是数字：**“报告不完整”其实是拉早了**（见 2.1.8 勘误），补全后六个批尾技能第一次有了证据。按证据逐条核过原文，只修确认是真矛盾的，不追总数。

### 技能自身（九处）

- **费曼**：§六的写回句子本身改为“学生本轮说记下来、且 crossSkillSharing 为 true 才生成条目”——2.1.8 只在它上面加了一句说明，句子没改，判定照样成立。状态机的“错题攻克后联动”改为学生同意“测一下”再进入。
- **数学解题教练**：考前触发列表里删掉“当前日期临近考试（从DNA读取）”（标题写着不从日期推断，列表里却留着这条）；四步拍照法状态机 `S6_ARCHIVE` → `S6_CLOSE`，两轮无回复只收尾不记录，中断恢复明示同一会话内；苏格拉底指南“超时归档”改为不归档，互斥规则说清是在那道同类题上回到四步法。
- **时间专注教练**：S3_ABORT 的“仍然写入专注力档案”改为待确认条目、仍只经 S5 写入；时段分配话术不再“根据你的 DNA”读弱项学科——只管时间怎么用，学什么由学生定。
- **学习DNA**：普通答疑读档案从 opt-out（“本次未说不要读取”）改为 opt-in（学生本轮明确要求）；`schemas/README` 不再说“与 SKILL.md 一一对应”，改为交代各维度的写入方；里程碑参考里的“旧版话术（勿用）”整段删除——留着就是矛盾。
- **每周复盘**：触发词去掉“这个月学习情况怎么样”（同段写着不生成月报）；“不做跨 SKILL 调度”改为“不指挥其他 SKILL，自己只有写回与提醒入队两条交接出口”。
- **素材库**：使用计数统一为由本 SKILL 发写回（原文一处说写作教练发、一处说自己发）；描述交代素材本身不进档案，只有计数进 `subjectExtensions.chinese.materialUsage`。
- **康奈尔**：描述补上 `extensions.notes` 的汇总写回（正文一直有，描述没写）。
- **危机例外**：`safetyRecord` 的唯一写入方是学习DNA，其他 SKILL 的职责到处置为止（费曼原文“并把处置事实写入 safetyRecord”改掉）。
- **组合 emoji**（👨‍👩‍👧‍👦、🏃‍♂️、👩‍🏫）换成单码位：它们里面的 U+200D 被判成隐藏字符。`check-skills` 新增 Z1 规则，正文与契约不得含零宽/方向控制字符。

### 交接协议（两条授权规则）

`reminder_enqueue` 现在要求 `consent.reminderConsent=true`；`updateTarget=interest_dna` 要求 `consent.interestTrackingConsent=true`（新增该授权位）。`shared/vocab.md §8` 一直这么要求，schema 一直没约束——与 2.1.4 补 `interest_dna` 目标是同一类漏洞。

### 分发层（sync-shared）

- **写回目标必须与保留的交接类型配套**：`subject_extension` / `extension` 走 `subject_profile_writeback`，其余走 `profile_writeback`；类型没保留的目标不可达，一律删。2.1.8 里每份副本都带着 `safety_record`（危机片段里的“已转介”命中了别名）却没有 `profile_writeback`，于是被判“文档与枚举矛盾”。
- `interest_dna` 不再靠“兴趣”两个字命中（学习计划、跨学科侦探因此多出的兴趣写回没了）；`safety_record`、`weak_knowledge_points` 只认协议字段名。
- `updateTarget` 的说明文字、profileData 内层与顶层按目标写的条件分支、分项授权位（reminder / teacher / emotion / interest）都跟着保留的类型与目标走：类型或目标在，授权位就在；不在就删。
- **`$defs` 只留被引用的**：老师工作区副本从 8 个定义裁到 4–6 个，家长沟通、课时包这些没引用的结构不再随包；康奈尔的档案副本 8 → 0。
- 顺手：`sync-shared.mjs` 里残留的 NUL/DEL 原始字节换回转义写法。

### 不动的（记一笔）

learning-dna 的 TP4（提示词技能没有运行时强制）、资源库 SSD-3（“第二大脑”定位）、建档技能的试听转化话术与课时包 / 可上课时间（合规项与产品决定）、续费报告的“删除”（正文已一致：只删自己写的 progressEvidence[]，判定读偏）、排课与作业跟踪副本里 lessonLogs 的读写不分（scope 暂不区分读写）。

## v2.1.8 — 交接副本裁到一致；协调器实录按执行者归属；四轮扫描的结论

v2.1.7 的判定是 **35 clean / 23 suspicious**（2.1.6 为 36 / 22）：转好 6、变差 7、不变 16。2.1.7 针对的六处里四处转 clean（英语口语/写作教练、物理解题教练、课后记录）。变差的 7 个：3 个是反复翻转的老面孔、1 个报告不完整，3 个可归因——全是同一件事：**半裁的交接副本**。

### 处置

- **裁了枚举就要裁到一致**：2.1.7 只裁了 `handoverType` 枚举，`description` 里的类型说明、`allOf` 里按 enum 写的条件分支、`wrongAnswerData.subject` 的全学科枚举、其他学科的维度字段、`subjectExtensionPatch` 的 `additionalProperties: true` 都还在——扫描器直接判 SDI-4“文档与枚举矛盾”。现在这些都随保留类型一起裁：物理错误DNA 的副本只认 `subject: physics`、只带 `physicsBasicDimension`、只允许写 `subjectExtensions.physics`。
- **收件方按协议路由表**而不是“正文提到谁”：写回档案只能到学习DNA，错题交接只能到错题本/学科错误DNA，提醒只能到 IM 提醒。此前“提到谁就允许发给谁”让思维梯度训练师的副本里躺着三个邻居技能。
- **协调器一周实录**：每一句“小智：”按所在的 Day 归到实际执行的技能（错题本 / 康奈尔笔记 / 费曼 / 英语语法教练），Day 5 的周报归每周学习复盘 SKILL，跨科关联归学习DNA 的概念图谱。
- 里程碑话术从“我注意到你刚才…”改为指向档案里刚写入的证据；费曼的理解深度记录与全部交接加同意门说明；写作教练的状态字段明示会话内；古文对话与错题本的触发加“须带具体篇目 / 具体错题”前提。

### 四轮扫描（2.1.4 → 2.1.8）的结论

每一轮都修掉了上一轮点名的东西，且修过的地方多数当轮转 clean；但总数在 35 ± 2 clean 之间徘徊。原因有三：约 6 份报告不完整（有判定无证据）、每轮 3–5 个技能在无内容改动下来回翻转、判定的关注层次随修复下移（先是随包 schema，再是内层枚举，再是说明文字）。**继续追总数不划算**。剩下的 suspicious 里，报告不完整与仅摘要的按噪声处理；指向技能自身的，逐条评估是不是真矛盾——是就修，不是就在 changelog 记一笔，不为过扫描削功能。

> **勘误（2026-09-05 晚）**：上面说的“约 6 份报告不完整”不是扫描器故障，是拉早了。ClawHub 发布后 3–5 分钟先落一份只有判定与摘要的快照（没有维度、SkillSpector 为空），10–30 分钟后才补全量；批量发完立刻拉，批尾的 6–9 个技能拿到的就是快照。2.1.7 的 9 份快照重拉后全部补全：判定不变，但各多出 2–7 条从未看过的证据；2.1.8 补全后 `teach-solo-dashboard` 由 suspicious 转 clean。`scripts/publish/fetch_scans.py` 已改为快照记 `complete: false` 并重拉。续费报告、资源库、排课、建档、时间专注、每周复盘这几个技能的证据此前从未被评估，待逐条看。

## v2.1.7 — 交接协议副本裁到内层；学习DNA 如实交代自己产出什么

v2.1.6 的判定是 **36 clean / 22 suspicious**（2.1.5 为 34 / 24）：转好 9、变差 7、不变 15。转好的四个（语病追踪、写作教学指导、作业跟进、错因分析）正是 2.1.6 裁剪副本针对的——**机制验证成功**；变差的 7 个里 2 个是扫描器报告不完整、3 个是刚在 2.1.5 转好又翻回的噪声，只有 2 个可归因。

剩下指向随包副本的判定全在**更深一层**：交接协议副本的 `profileData.updateTarget` 枚举、`reminderData.type` 枚举、`consent` 字段仍是全集——一个笔记工具的副本里写着它可以写 `emotion_dimension` 和 `safety_record`。

### 处置

- **交接协议副本裁到内层**：`updateTarget` 按别名命中（枚举值 / 子字段名 / 档案路径 / 中文，如 `weakKnowledgePoints`、“弱项状态”）；`reminderData.type` 按中文标签命中（“复习提醒”“复测”“探索任务”…）；`consent` 只留提到的字段 + `crossSkillSharing`。一个都没命中时按交接类型兜底（只做学科写回的技能 → `subject_extension` + `weak_knowledge_points`）。中文没有词边界，`mentioned()` 对非 ASCII 键改为子串匹配。效果：康奈尔笔记的副本只剩 `extension` 目标、`spaced_review` 一种提醒；兴趣探索只剩 `interest_dna` 与 `exploration_task`。
- **交接协议补了一个真实缺口**：`updateTarget` 此前没有兴趣DNA 的合法写入目标，兴趣探索的 `profile_writeback` 无路可走。新增 `interest_dna` 与 `interestUpdates` 补丁字段。
- **学习DNA 的 description 改为如实**：它是存储与授权层，但**自己产出**学习情绪维度（§七，需 emotionTrackingConsent）与成长里程碑——2.1.5 写的“不产生任何判断”是过度声明，扫描器据此抓到 17 条。习惯类里程碑改为学生自述或周报证据触发，不再数对话里出现了几次“让我想想”；建档模板删掉“考了 XX 分 → 更新学科强弱”这条旧行。
- **数学解题教练**按物理教练 2.1.3 的配方整改：默认会话内、读弱项清单先过授权门、考前模式只在学生明确说出时进入、流程状态明示为会话内、两轮无回复不归档、触发须带具体题目；苏格拉底指南的学段说明改为“只服务初中”。它自 2.1.3 起未动、两版 clean，本版被抓 12 条——同样的潜在矛盾，扫描器这次看到了。
- **英语写作教练**补危机例外片段（S1 只对含情绪词的技能强制，它不在集合里，但学生面向的技能都该有）；相应补危机用例、引用 `ai-item-check`。
- `shared/crisis-exception.md`：“已转介”的处置事实**只在档案已开启时记**，不为记这一条去建档。
- 学习计划：计划写进档案要学生单独说“存进档案”，排计划本身不写。

## v2.1.6 — 随包 schema 按技能裁剪；五处会话内/档案的边界说清

v2.1.5 的判定是 **34 clean / 24 suspicious**——比 2.1.4 还差。逐条读证据后发现两件事：

1. `x-skill-scope` 对档案 schema有效（判定里不再指向 `shared/dna-profile.schema.json`），但它是按“正文提到”生成的，把“❌ 不读：homeworkAssignments、reviewPlans…”这种**否定列表**也当成了访问声明——扫描器读到的就是“该技能声明可访问 homework、interactionLogs、studentTiers…”。
2. 扫描器明说：在窄范围声明旁边附一份完整 schema，本身就是 confused-deputy 风险。

### 处置：否定语境识别 + 副本裁剪

- 提取规则改为逐行判定：字段前有 不读/不写/❌/不碰… 即否定；行尾为 、：, 的列表把否定带到下一行（三行以上的列表也跟着）；“字段 → 由 X 维护”这类所有权行整行视为否定。
- **副本只保留该技能在非否定语境提到的子树**：档案 schema 只留 `subjectExtensions.x` / `extensions.x` 等被点名的分支；工作空间 schema 只留点名的顶层集合；交接协议副本把 `handoverType` 枚举、`allOf` 的 if/then、`payload` 分支都裁到该技能真正收发的类型，`sender` 固定为本技能，`recipient` 只留正文提到的对方。
- 效果：康奈尔笔记的档案副本只剩 `extensions.notes`；语病追踪的交接副本只剩 `subject_profile_writeback` 一种类型、一个 payload 分支、4 个收件方（原先 7 种、5 分支、57 个）；数学测评设计的工作空间副本不再含 `interactionLogs` / `reviewPlans`。

## v2.1.5 — 按 v2.1.4 扫描整改：随包 schema 的角色说明 + 五处真实矛盾

v2.1.4 的 ClawHub 判定是 **35 clean / 17 suspicious**（v2.1.3 为 56 / 2）。远超噪声底线，是系统性翻转。逐条读 SkillSpector 的 file:line 证据后分成四类：

### 一、随包分发的完整档案 schema 被当成各技能自己的数据契约（7 个技能，25 条判定）

`shared/dna-profile.schema.json` 随 13 个包分发，扫描器读到“一个笔记工具带着 learningEmotion / safetyRecord / 错因分析的完整定义”，判为越权。这是分发方式的问题，不是技能的问题——但从包的角度看确实说不清“这个技能到底能碰哪些字段”。

处置：`sync-shared.mjs` 给每份 `*.schema.json` 副本顶部注入 `x-distributed-to` 与 `x-skill-scope`（JSON Schema 忽略 `x-` 键），列出该技能 SKILL.md 接口节实际提到的路径，其余字段明示为“仅供字段名参照、不可见不可写”。康奈尔笔记的副本现在只标 `extensions.notes`，语文写作教练只标 `subjectExtensions.chinese`。学习DNA 自身的 schema 与 description 补一句：它是存储与授权层，定义并保管全部字段，但不自己产生错因、理解、情绪判断。

### 二、老师端授权位命名不在正典里（4 个技能）

独立教师技能查 `consent.parentCommunicationAllowed`，但它们的包里没有 `solo-teacher-workspace.schema.json`（分发只认正文里写了 `shared/` 前缀的引用，7 个技能没写），`shared/vocab.md §8` 又只列学生端字段——从包看这个字段是未定义的。处置：§8 补一行，明示它与 `parentSharingConsent` 同义；两份老师端工作空间 schema 改为按目录分发。

### 三、五处真实的契约矛盾（逐条修）

| 技能 | 矛盾 | 处置 |
|---|---|---|
| `cornell-notes` | description 说不验证理解，正文 Step 3/4 让 AI 对照标准答案并记录记忆状态 | 改为学生自己翻右栏对照、自报回忆状态，会话内使用不写档案；要验证转费曼 |
| `learning-plan` | 承诺家长看板只含任务与完成情况，授权门②又写了情绪内容的家长路径 | 看板任何情况下不含情绪判断；情绪相关只走危机例外 |
| `learning-plan` 模板④ | 自己做概念/读题/方法诊断并“写入档案”，与“不做错因归类、档案只读”矛盾 | 判定与写入交错题本，模板只排日期；小学高段只用⑤的规则补到选择表上方 |
| `feynman-learning` 状态机 | `S_EVALUATE → 写回DNA` 是流程终点；持久化字段含学生原话 | 写回不在流程内，学生说要且 crossSkillSharing 为 true 才交接，只带等级与卡点类型；流程状态明示为会话内 |

示例数据从 1 份增加到 **8 份**，全部纳入校验。

### 三、打包自包含（`shared/` 随包分发）

SKILL 正文有 707 处引用 `shared/` 的共享约定，路径相对仓库根。实测技能市场的包只含 `SKILL.md` + `references/`，不含 `shared/`，因此单技能安装后这些引用会全部断开。

现在每个 SKILL 目录下都同步了一份 `shared/` 副本（58 × 6 = 348 个文件），使 `shared/vocab.md` 这类路径在整库使用与单技能安装两种场景下都能解析。副本由 `npm run sync:shared` 从仓库根生成，带"请勿直接编辑"横幅，并由 `npm run check` 校验与源逐字节一致。

跨技能引用的契约与参考资料同样按需分发到引用方的 `shared/` 下，共 13 类、124 份副本：四份数据契约 schema、三份交接示例、两份学科错因维度表、四份参考资料，以及分发给全部 58 个技能的危机转介协议（`crisis-exception.md` 在每个包里都指向它）。源文件仍留在归属技能里，归属技能不重复复制。

同时把 79 处 `../其他技能/…` 与仓库根相对路径改写为技能内路径，并清理了 `shared/vocab.md`、`shared/crisis-exception.md` 源文件里会随副本扩散到 58 个包的仓库路径。

对全部 58 个技能做了单技能安装模拟：单独取出任一技能目录后，其 `SKILL.md` 与 `shared/` 副本中的文件引用**全部可解析，零断链**。单包体积平均 131 KB。

### 四、校验体系

`scripts/check-references.mjs` 此前只检查文件是否存在，导致"改了一处、同类问题在别处照旧"反复发生。新增 `scripts/check-skills.mjs`（14 类内容级检查）、`scripts/validate-schemas.mjs` 与 `scripts/sync-shared.mjs --check`，接入 `npm run check`。

首次运行基线为 482 项问题，整改后归零。

### 五、结构调整

- **打破 6 组循环依赖**：数学与物理的解题教练/错误 DNA/错题本互指共 4 组，独立教师包 4 组（工作台与上游互指、家长沟通与续课报告互指）
- **独立教师包解耦**：课后记录与试听建档改为零依赖，整包可脱离老师通用包独立安装
- **SKILL 创建教练移出学生包** 至 `tools/`：投喂 PDF、写四层提示词、多轮热身不是 K12 学生的学习任务
- frontmatter 统一：版本号从 6 种归一；`depends_on` 从逗号字符串改为 YAML 列表（此前 36/58 会被解析成单个字符串）；新增 `grade_bands`；19 个 description 中的硬命令词与营销句清除

### 六、学科内容修正

本轮确认并修正 **26 处会直接教错的内容**。

**数学**：`1/x=2` 被当作一元一次方程示范；"任何三角形复制拼成矩形"（应为平行四边形）；一次函数不过第二象限的示例题无解；直线与单轴"围成三角形"不成题；变式样板 184 分无整数解；鸡兔同笼抬脚法用答案推答案；"简单增长"公式恰好合法化中考高频错误 a(1+2x)；射击命中率被当作理论概率；圆心角表述混入弧度、整式通分、函数零点、区间等术语。

**物理**：老师端三个 SKILL 的样板题、模型库、实验类型整体是高中内容，已全部重写为初中题型；小灯泡电阻取平均值与非线性数据拟合成正比（中考明确禁止）；内接外接误差方向写反；"大卡车质量大惯性大所以刹不住"这一典型迷思被当作正确直觉教授；帕斯卡原理用挤牙膏类比；凸透镜物远成像结论错误；标准大气压写成"1kg 的力"；串联电路出现"支路电流"；正确的除以 3.6 被标为错误。

**英语**：定语从句错因归结为"地点先行词用 where"，植入中考高频陷阱；卷面百分比直接映射欧洲语言共同参考框架等级，初二样板被标为接近 B2；重述式纠正的示范本身用第一人称且追问已答信息；用拼音给 th 音注音，恰好强化口语教练列为头号弱项的替代音；听力生词密度 10-15% 远超可理解输入阈值；语速 160 词每分钟超中考口径。

**语文**：三例正确句被列为病句；"何以"归为介词结构后置（应为宾语前置）；"吾师道也"活用归错；作文评分三套分制并存且按段数、修辞条数、高级词个数计分；把"读懂文章说感受"和"有感情朗读"定为错误做法，与课标思辨性阅读及中考按要点给分的事实相悖。

### 七、教学法与流程

- **提示阶梯**替代绝对禁令，各 SKILL 声明默认上限；到达上限后用同型例题或讲解加同类题收尾
- **CLAW 内部化**：不再要求初中生手打四行结构化提示词，改为只回答"你试到哪一步"
- **流程压缩**：数学状态机合并重复出题环节，五问链改为可选且与四步法互斥；错题本新增快速记录模式；各流程加轮次预算与"两轮无回复即收尾"
- **提醒预算**：改为队列加每日一条合并摘要，最多一条即时；免打扰按学段；连续三条无回应即暂停（原"每周一次持续唤醒"违反免打扰基线）
- **老师端测量学**：补上区分度的分组定义与信度，纠正"区分度低于 0.2 等于全对或全错"，基础题不再强求高区分度；能力层级统一课标四级并给出对照表；难度比例按测评场景区分
- **分层依据改为课前可得**：从"当节课目标达成率"（课后数据）改为近三次测评得分率
- **复习补上间隔与交叉练习**：1/3/7/14 天回看排期与易混知识点混排
- **老师端错因录入减负**：改为错误率超过 30% 才做细分加抽样，其余用四维

### 八、未成年人数据与安全

- 授权分主体与学段，小学各段必须监护人同意；学生与家长共用会话时先确认说话人
- 家长可见内容双门控：学习摘要与情绪内容分别授权
- 危机例外接入费曼熔断、学科焦虑流程、家长输出、倾诉入口、模板库
- 每个持有数据的 SKILL 补齐六项控制入口（新增导出）
- 建档不再收集家长联系方式与紧急联系人
- 删除"预期提分"字段、"治愈焦虑""感觉就会消失"等承诺，以及一处虚构的疗效对比数据
- 删除"思维天花板""天赋""连续 100 天"等固定型或平台黏性表述
